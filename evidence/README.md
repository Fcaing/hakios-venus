# evidence

只有两份摘录，因为**"能在原始日志里核对的结论"比"看起来很多的截图"更值钱**。

| 文件 | 是什么 | 为什么留它 |
|---|---|---|
| `p431-loopback.txt` | LOOPBACK 通道（ch0 → ch1）双向跑通那一段：TRE、门铃、缓冲区回读、两个事件 TRE | 这是本项目**唯一的正对照**。没有它，"设备没反应"和"我们没发对"永远分不开 |
| `p468-channel-contexts.txt` | `pcie_chanstart=0` 时设备自己把 ch20/ch21 建好（`0x202`）；以及 `0x0200` 会让 AMSS 起不来 | 它一次性关掉了"调通道上下文内容"这条歧路，并且推翻了更早一条错误结论 |

两份都不是原始整包日志（每轮 250 KB 左右、含大量 GPU 噪声），只保留结论行；每份开头写明了
来源文件、轮次 tag、以及"能从中读出什么"。

---

## 原始日志怎么自己生成

```powershell
& $FB oem dump logdump 0 40000 ; Start-Sleep 5
& $FB get_staged ".\cur-pNNN.bin"          # 262,144 B
.\extract-log.ps1 -File .\cur-pNNN.bin -Out .\pNNN.txt
```

注意三件事：

1. `logdump` 里保留着**历史启动**，必须先按 `pcie_tag=pNNN` 切片；
2. 只取以 `the probe is done…(apply-169)` 结尾的**最新**时间戳组；
3. iOS 桌面起来后 GPU 每秒刷 20+ 行，日志环只有 1 MB，**中段打印会被冲掉**——重要结论要放在最后一次 `printf` 附近。

## 为什么不把 p416–p487 全部放进来

- 每份 ~250 KB、含二进制式噪声，300 份就是 ~75 MB，对仓库没有增益；
- 它们只对"当时那一版驱动"有意义，而那版驱动已经丢了；
- 结论已经沉淀到 `docs/02-wifi-status.md` 的表格里，需要核对时按轮次号回你自己的私有日志。

如果你要接手，建议保留**自己**的 `pNNN.txt` 私有副本（已列入 `.gitignore`），不要提交。
