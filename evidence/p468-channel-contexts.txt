# p468 - the channel contexts are written by the firmware, not by us

Source: `venus-recon/p468.txt`, same extraction path. This round ran with
`pcie_chanstart=0`: the host never published a channel context.

What it shows: before the host touches anything, ch20 and ch21 already read `0x00000202`
(RUNNING + burst mode 2) with ring bases `0xa020c000` / `0xa020d000`. Publishing `0x0202`
at handover is what lets AMSS boot; publishing `0x0200` (chstate 0) keeps it from booting
at all.

Two consequences this project had to learn the hard way:

  * the firmware builds these channel objects itself and does read them during the
    SBL -> AMSS handover, so "channel context content" was never the variable to tune;
  * "the device never wrote a context" (round p398) was a misreading of a round in which
    the host had already written it.
